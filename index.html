How the calculator works

Basic formula

Basic mode is intended for quick estimation when you only know the approximate number of users and data size.

Concurrent Users = Total Users × Concurrency % Effective Concurrent Load = Concurrent Users × Workload Factor HTTP Workers = ceil(Effective Concurrent Load / 6) Worker Equivalent = HTTP Workers + 2 Cron Workers Minimum CPU ≈ (Worker Equivalent - 1) / 2 Recommended CPU = Minimum CPU + 30% headroom RAM ≈ Worker Equivalent × 512 MB + PostgreSQL + OS/services + cache + 25% headroom Future Data = (Database + Filestore) × (1 + Annual Growth Rate) ^ Planning Years Storage ≈ Future Data + WAL/Temp Reserve + Backup Copy + Safety Margin

Advanced formula

Advanced mode expands the workload estimate so you can model heavier transaction rates, custom modules, scheduled jobs, queue jobs, memory usage, and storage requirements separately.

Effective Concurrent Load (ECL) = Concurrent Users × Workload Factor × Transaction Factor × Customization Factor HTTP Workers = ceil(ECL / Users Per Worker) Worker Equivalent = HTTP Workers + Cron Workers + Queue Worker Equivalent Minimum CPU ≈ (Worker Equivalent - 1) / 2 Recommended CPU = Minimum CPU × (1 + CPU Headroom) Odoo RAM = Worker Equivalent × Average Worker RAM Recommended RAM = (Odoo RAM + PostgreSQL RAM + OS / Services + Cache) × (1 + RAM Headroom) Observed Growth Per Month = Growth GB converted from Day / Week / Month / Year Future Data = Database + Filestore + (Observed Growth Per Month × Planning Months) WAL / Temp Reserve = Future Data × WAL Reserve % Backup Storage = Future Data × Backup Copies Recommended Storage = (Future Data + WAL / Temp Reserve + Backup Storage) × (1 + Storage Safety)

Important notes

This calculator is a capacity-planning aid, not a guaranteed sizing rule. Real Odoo performance depends heavily on PostgreSQL query performance, custom modules, computed fields, automated actions, cron jobs, queue jobs, POS traffic, reporting patterns, integrations, and storage latency. For an existing production system, observed peak CPU, worker RSS, PostgreSQL memory, slow SQL, requests per second, queue load, and transaction volume should replace generic assumptions wherever possible.
